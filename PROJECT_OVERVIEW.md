# Проект «Шпион» — описание для code review

## Что это
Android-игра «Шпион» (party game) на Kotlin + Jetpack Compose. Архитектура **гибридная**: телефон-хост поднимает у себя встроенный веб-сервер (Ktor), а остальные игроки подключаются к нему через **браузер** (Android/iPhone — любой) по локальной WiFi-сети. Устанавливать приложение нужно только хосту.

- Хост = Android-приложение + встроенный сервер + сам является игроком (управляется из Compose UI).
- Игроки = браузерная страница (одна большая HTML/CSS/JS-строка, отдаётся сервером).
- Связь: WebSocket, сообщения в JSON (kotlinx.serialization, дискриминатор `type`).
- Всё в локальной сети, интернет не нужен.

## Стек и версии
- Kotlin 2.2.10, Jetpack Compose (Material3), AGP 9.2.1, Gradle 9.4.1
- compileSdk 37, minSdk 24, targetSdk 36
- Ktor 3.0.3 (server-core, server-cio, server-websockets, content-negotiation, serialization-kotlinx-json)
- ZXing (QR-код), coreLibraryDesugaring (для java.time на minSdk 24)

## Игровая механика (важно для проверки логики)
Ядро — режим «похожие слова». Каждому игроку тайно выдаётся слово. По кругу все называют ассоциацию, потом голосуют, кто лишний.

**Роли** — enum `Role { CIVILIAN, SPY, MR_X }` в `Protocol.kt`, хранится в `Player.role`.
Вся логика (очки, итоги, приём догадки) ходит через роль. Строка `GameState.MR_X_WORD = "???"`
осталась только как то, что Mr. X ВИДИТ вместо слова; сравнивать с ней в логике нельзя.
Клиентам явная роль приезжает флагом `RoleAssignment.isMrX`.

**Три режима (задаются в лобби ведущим):**
1. **Только шпион** (spyCount ≥ 1, hasMrX = false): большинство получает слово X, шпион(ы) — похожее слово Y из той же категории. Мирные ищут шпиона по ассоциациям.
2. **Только Mr. X** (spyCount = 0, hasMrX = true): все получают одно слово, кроме Mr. X — у него нет слова вообще, он знает ТОЛЬКО категорию и блефует по чужим ассоциациям. Если пойман — выбирает слово из 6 вариантов той же категории.
3. **Шпион + Mr. X** (spyCount ≥ 1, hasMrX = true): и шпион (похожее слово), и Mr. X (без слова).

**Ограничение состава (баланс):** Mr. X раздаётся, только если после его добавления
мирных остаётся СТРОГО больше, чем лишних. Единственное исключение — единственный лишний
на двоих игроков (тестовая дуэль). Поэтому «1 шпион + Mr. X» требует минимум 5 игроков;
на троих роль молча пропускается, а лобби заранее пишет об этом ведущему.
Шпионов по-прежнему не больше `active.size / 3`.

**Победа:**
- Лишний (шпион ИЛИ Mr. X) пойман голосованием + не угадал слово → мирные победили.
- Пойман + угадал слово мирных → ничья.
- Никого из лишних не поймали → победили лишние (плюс бонус, если кто-то угадал слово).
- При равенстве голосов — переголосование между лидерами (один раз), потом «никого не обвинили».
- Итог приезжает клиентам полем `RoundResult.outcome` (CIVILIANS / IMPOSTORS / DRAW / NONE) — по нему красится экран.

**Очки партии** (копятся, пока живёт сервер). Принцип: платим за дедукцию, а не за удачу
оказаться в победившей команде.
- Мирный: **+2** лично за голос точно в лишнего (даже если общий голос ушёл не туда), **+1** сверху, если лишнего в итоге поймали.
- Непойманный лишний: шпион **+4**, Mr. X **+5** (роль сложнее), **+1** за угаданное слово мирных.
- Пойманный лишний, угадавший слово: **+2** (ничья).
- Лишний уцелел, но спалился напарник: половина награды (шпион +2, Mr. X +3) — раунд команда проиграла, но лично он отработал чисто.

## Ключевые детали реализации (на что смотреть при review)

### GameState.kt
- Хост регистрируется как игрок с фиксированным `HOST_ID = "HOST"`, `ensureHost()`, всегда `connected = true`, добавляется в `order` на позицию 0.
- `startRound()`: выбирает пару слов (без повторов, `usedPairs`), случайно решает какое «мирное»/«шпионское» (flip), назначает шпионов через `shuffled.take(spyN)`, Mr. X — случайно среди НЕ-шпионов (`random(random)`).
  - `minSpy = if (hasMrX) 0 else 1`; защита: если !hasMrX и spyCount<1 → 1.
  - Mr. X назначается только если мирных остаётся больше лишних (см. «Ограничение состава»).
  - Порядок речи (`speakingOrder`) перемешивается ОТДЕЛЬНЫМ shuffle — иначе шпионы всегда шли бы первыми.
- `computeResult()`: подсчёт голосов (tally), обвинённый = единственный с макс. голосами (иначе null). Ветвление по ролям, не по словам. `spyGuess` проверяется через `equals(civilianWord, ignoreCase=true)`. Раскрывает и шпионов (`spyIds`/`spyNames`), и Mr. X (`mrXId`/`mrXName`).
- `setSpyGuess()`: принимает догадку ТОЛЬКО в `VOTING` (от любого лишнего) и в `FINAL_GUESS` (только от самого обвинённого) — иначе лишний мог дослать ответ после развязки и добрать бонус задним числом.
- `castVote()`: только участники раунда (`word != null`) — зритель, вошедший посреди игры, получает отказ + Notice, а не молча проглоченный голос.
- `computeResult()`: если раунд прошёл через «последнее слово», обвинённый берётся из `finalAccusedId` (он уже объявлен всем), а не пересчитывается по tally — иначе кик обвинённого «повышал» второе место до обвинённого. Кикнули объявленного → обвинение несостоялось (accused = null).
- `roleFor()`: `guessOptions` — ОДИН общий список из 6 слов у всех игроков (внутри и слово мирных, и слово шпиона как приманка), поэтому наличие списка никого не выдаёт.
- `GameSettings.autoSeconds(n)` — авто-таймер `30 + 25*n`, зажатый в 90…420 сек. Используется и сервером, и превью в лобби (одна формула на оба места).
- `settings.categories` — выбор категорий из лобби (пусто = весь банк).
- `currentSpeakerId()`: по `speakingOrder`, фильтр по участникам раунда (обрыв связи не сдвигает очередь).
- `kickPlayer()`: хоста кикнуть нельзя.

### GameServer.kt
- StateFlow для UI хоста: `phase`, `players`, `playerCount`, `timerSeconds`, `lastResult`, `hostRole`, `currentSpeaker`.
- `init { state.ensureHost("Ведущий") }`.
- `install(WebSockets)` без параметров (дефолты).
- Хост-команды: `hostStartRound`, `hostNextSpeaker`, `hostStartVoting`, `hostBackToLobby`, `hostUpdateSettings`, `hostUpdateName`, `hostKickPlayer`, `hostVoteFor`, `hostSpyGuess`.
- Таймер обсуждения (`startDiscussionTimer`) тикает каждую секунду, по истечении сам запускает голосование.
- При Join: если раунд уже идёт, переподключившемуся шлётся его роль.
- Голосование завершается когда `allVoted()` (все connected проголосовали).

### ClientPage.kt (браузерный JS)
- Всё в одной строке `"""..."""`. Переподключение по токену (`onopen` шлёт Join с сохранённым token).
- Токен и имя хранятся в `sessionStorage` (per-tab!) — обновление страницы не создаёт дубль игрока; при Kicked токен стирается. `localStorage` нельзя: два игрока с одного телефона в разных вкладках затирали бы друг друга.
- Зритель (вошёл посреди раунда, `myWord == null`) видит экраны «вы зритель» в обсуждении и голосовании вместо кнопок.
- Флаг `kicked` — после кика не переподключаться.
- Сохраняет `myWord`, `myCategory`, `myGuessOptions`, `myIsMrX` из RoleAssignment; сбрасывает в Lobby.
- Показывает своё слово всё время на экране обсуждения (иначе Discussion-тик перерисовывал бы без слова).
- Mr. X определяется флагом `msg.isMrX`, а НЕ сравнением `myWord === "???"` (раньше правка строки-заглушки молча ломала половину экранов).
- Итог красится по `msg.outcome`.
- Правила (`getRulesText`) зависят от `lobbySpyCount` / `lobbyHasMrX`, приходящих в Lobby-сообщении.

### Protocol.kt
- ClientMessage: Join(name, token?), Vote(suspectId), SpyGuess(word), Ping.
- ServerMessage: Joined, Lobby(players, phase, minPlayers, spyCount, hasMrX), RoleAssignment(word, category, youMayBeSpy, roundNumber, guessOptions), Discussion, VotingStarted, VoteProgress, RoundResult, Notice, Kicked.
- Все с `@SerialName` (короткие имена в JSON).

## Известные не-баги (это by design, НЕ надо «чинить»)
- При 2 игроках голосование всегда даёт равенство (каждый за другого) → «никого не обвинили». Это осознанный тестовый режим (minPlayers=2 сделан ради тестирования на 2 телефонах).
- Хост не голосует за себя (отфильтрован), но браузерные игроки видят его в списке и могут за него голосовать — это корректно.
- Клиентские тексты частично на транслите в некоторых служебных строках — если увидишь, можно указать, но это косметика.

## Что проверить (запрос к ревьюеру)
1. **Логика computeResult** во всех трёх режимах — правильно ли определяется победитель, особенно граничные случаи (0 шпионов, Mr. X отсутствует хотя hasMrX=true из-за нехватки игроков, все проголосовали одинаково).
2. **Гонки/потокобезопасность**: GameState под `synchronized(lock)`, но StateFlow обновляются из разных корутин — нет ли рассинхрона между состоянием игры и тем, что видит UI.
3. **Назначение ролей в startRound** — действительно ли Mr. X и шпион выбираются равновероятно среди всех (был баг: Mr. X всегда становился хостом при 2 игроках — исправлен через `candidates.random`, проверить что фикс полный).
4. **Переподключение**: игрок обрывает связь и заходит снова по токену — сохраняется ли роль, не создаётся ли дубль.
5. **Кик**: корректно ли удаляется игрок из `players` и `order`, закрывается ли сессия, не ломается ли идущий раунд/голосование если кикнули голосующего.
6. **Таймер**: если хост вручную запускает голосование до истечения таймера — не запустится ли голосование дважды (таймер + ручной вызов).
7. **guessOptions для Mr. X**: всегда ли правильное слово (`civilianWord`) входит в 6 вариантов.
8. **Синтаксис встроенного JS** в ClientPage.kt (это строка внутри Kotlin — компилятор её не проверяет).
9. **Edge cases**: игрок заходит в середине раунда; все игроки вышли; хост сворачивает приложение (сервер в onDestroy останавливается).

## Как собрать
Открыть в Android Studio → Gradle Sync → Run на телефоне. Требуется Android SDK 37. Остальные игроки открывают в браузере `http://<IP-хоста>:8080` (показывается на экране + QR).
